# SwiftDictionary U3.0 — Phase 2 Malay Dictionary Execution Plan

**Status:** Phase 2 authorised and started on 2026-11-26. This is the implementation contract for the Malay Dictionary phase, not a claim that Malay is active or ready for public release.

**Application baseline:** U3.0 Phase 1 validated feature branch `feature/update-3.0-phase-0-audit`, commit `c2dfc3bd1887c4ee1d4b821520f305726303922c`.  
**Production baseline:** Update 2.9.1.  
**Language:** Malaysian Standard Malay (`ms-MY`).  
**Phase boundary:** Dictionary content, language-owned package, linguistic search adapter and tests. No Malay Lessons, Daily Learning, Quiz, Flashcards, database activation, public course selection, production migration, merge or deployment.

## 1. Existing U3.0 contracts to preserve

- Shared registry code: `ms`; locale: `ms-MY`; script: `Latn`; status remains `planned`.
- Existing adapter registration: `malay`; extend it conservatively rather than adding language-specific branches to shared UI.
- Content contract: schema version 1; stable immutable `id`, `languageCode`, `contentVersion`, headword and one or more uniquely identified senses.
- Existing English/Chinese dictionary source arrays and legacy compatibility wrappers remain unchanged unless a regression fix is strictly necessary.
- English remains word-grid + IPA; Simplified Chinese remains one Han character per card + Pinyin and stroke-order behaviour. Malay uses whole lexical headwords/expressions as cards, with no Chinese geometry.
- The current package bootstrap deliberately creates only en/zh packages. Phase 2 may create and validate the ms package in isolation, but must not make ms selectable or activate it in the live runtime.

## 2. Malay lexical record contract

Each record is a Malay lexical headword/lemma with:
- stable ID independent of displayed wording or translations;
- schema version, language code `ms`, content revision and editorial status;
- canonical display headword and Malaysian part-of-speech label;
- pronunciation only when sufficiently supported; do not fabricate IPA or phonetic spelling;
- one or more senses, each with a stable ID, concise independently authored definition, context/register/domain where useful, and natural Malaysian example sentences;
- optional related headwords, collocations and grammatical notes;
- optional search forms for valid inflected/orthographic variants; aliases never create separate grid cards;
- translation/support-language records keyed to the stable source identity and revision;
- item-level provenance: authoring method, source/reference consulted, source version/date, licence/permission basis, editorial status and reviewer reference.

Do not force English-only fields such as Chinese character breakdown or English IPA onto Malay records. Keep the data extensible for later language packages.

## 3. Linguistic and search rules

1. Preserve Malay orthographic distinctions; do not remove meaningful diacritics as a generic normalisation step.
2. Search is case-insensitive and Unicode-normalised. Punctuation/spacing normalisation must not alter the canonical headword.
3. Search should match the canonical headword and explicitly recorded valid search forms. It must not search definitions, examples or editorial notes.
4. Model common Malay morphology deliberately: prefixes (`meN-`, `ber-`, `ter-`, `di-`, `peN-`, `ke-`), suffixes (`-kan`, `-i`, `-an`), circumfixes (`ke-...-an`, `peN-...-an`) and reduplication where relevant. These are descriptive categories, not permission to mechanically strip strings.
5. Search expansion must be lexically justified and conservative. Irregular allomorphy, spelling changes, lexicalised forms, passive/active voice, clitics and homographs require explicit mappings or review. Never stem blindly or treat every affix-like substring as productive morphology.
6. A derived form is not a separate headword unless it has an independent lexicalised meaning/use that warrants its own entry. Avoid duplicate grid cards for predictable inflections.
7. Related terms must be real, useful lexical relations (synonym, antonym, derivation, collocation or phrase) and the relation type should be recorded when possible.

## 4. Editorial scope and batching

Build a balanced general-purpose Malaysian Malay learner dictionary with an owner-requested target of approximately **700 unique headwords** (acceptable target band **650–750**). Prioritise high-frequency everyday vocabulary, communication, people, family, actions, places, time, food, objects, descriptions, education, work, health, travel, home, public services, nature, culture and common grammar/function words before specialist terminology. This is a coverage target rather than a quota: lexical accuracy, distinct headwords, sense quality, natural Malaysian examples and traceable rights status take priority over count. Include common Malaysian usage and context where appropriate without turning the package into a dialect glossary.

Content is authored in small sequential batches. Each batch is frozen and validated before the next is added. Do not invent a target record count to make a milestone look complete; report actual unique headword and sense counts, coverage by POS/category, unresolved items and review status. One consolidated deliverable is produced after Phase 2 has completed and passed validation; no intermediate ZIPs.

## 5. Provenance, copyright and licensing

- Prefer original definitions, examples and usage notes written for SwiftDictionary.
- DBP/PRPM and Kamus Dewan are reference authorities for checking Malaysian usage, spelling and senses. Do not copy their definitions, examples, entry text or bulk data into SwiftDictionary without written permission or a licence that explicitly permits the intended reproduction and redistribution.
- DBP's copyright notice states that reproducing any part of its data, articles, illustrations, audio, video or site content requires prior written permission from its Director-General: https://dbp.gov.my/hak-cipta/.
- Record the difference between a source used for linguistic verification and a source whose text/data is licensed for reuse.
- Do not scrape, mirror, reverse engineer or bulk-import DBP/PRPM/Kamus Dewan content. A public search result or public access is not a reuse licence.
- Any third-party corpus must have a verified licence compatible with a free public dictionary, attribution/share-alike obligations where applicable, and a documented transformation/reuse basis.
- Unclear provenance means quarantine the record; do not publish it by default.

## 6. Translation policy

- Malay is the authored source language for this package. English and Simplified Chinese are support languages, not alternate source records.
- Keep translations in the shared translation registry keyed by content ID, source language `ms`, target language `en` or `zh`, and source revision.
- Statuses must distinguish draft, machine-assisted draft, reviewed, approved, stale and not applicable. Approval requires a reviewer reference.
- Definitions may need multiple target-language equivalents by sense; never flatten distinct senses into one ambiguous translation.
- No automatic fallback to English text when a Chinese translation is absent, or vice versa. Surface a clear unavailable state where UI integration is later enabled.

## 7. Legal and privacy planning

This phase adds static lexical content and local search only. It does not add personal-data processing, tracking, external dictionary APIs or new account data. Before Malay is publicly activated, review the current Personal Data Protection Act 2010 as amended by Act A1727, the phased commencement notices, Commissioner circulars/guidelines, cross-border processing (production Tokyo; staging Singapore), privacy notice, retention/deletion, security, controller/processor roles and any registration/DPO obligations that apply to the actual project facts. The Commissioner publishes the Act, commencement notices and current guidance at https://www.pdp.gov.my/en/akta/personal-data-protection-amendment-act-2024/. Obtain competent Malaysian legal advice where needed; this is planning, not legal advice or clearance.
