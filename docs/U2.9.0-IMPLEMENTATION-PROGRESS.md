### Current structural validation (model-side cross-file audit)

- 277 authored headwords across six batches.
- 277 unique headwords across the authored batches.
- All 277 headwords are present in the candidate inventory.
- The 73 entries added in the latest continuation have the required text fields, two examples, sense records, valid course/category values and unique headwords.
- Candidate inventory status totals: 277 authored (across batch-specific statuses and the general authored status), 383 still candidates.
- A fresh cross-file structural audit of all six batches returned zero errors for duplicate headwords, missing required fields, malformed examples/senses, invalid course values, unapproved categories or missing candidate membership.
- The independent cross-file check identified a validator-rule mismatch: `related` is an optional related-word string and may validly be empty. The validator was corrected to require the field to be a string without requiring non-empty content.
- The corrected repository validator has not yet been executed in a checked-out Node/CI environment. The baseline `index.html` is too large for the current GitHub file connector to return its contents, so baseline duplicate validation remains pending execution in the repository environment.

These are structural/content-shape checks. They are not a substitute for the full linguistic review, native-quality translation review, runtime validation, or the final audit of all 810 existing entries.
