# SwiftDictionary U3.0 — Multilingual Architecture Contract

**Status:** Phase 1 implementation foundation. This document describes the target contract; it does not claim that all legacy runtime paths have been migrated.

## Platform and package boundaries

The shared platform owns navigation, authentication, preferences, account isolation, content loading, progress, allowances, history, translation lookup, common UI, and cross-language validation.

Each language package owns authored linguistic content and language-specific processing. Shared components must call a registered adapter/capability rather than infer behaviour from a language code.

## Registered languages

| Code | Language | Locale | Script | Phase 1 status |
|---|---|---|---|---|
| `en` | English | `en` | Latin | Active legacy migration target |
| `zh` | Simplified Chinese | `zh-Hans` | Han | Active legacy migration target |
| `ms` | Malaysian Standard Malay | `ms-MY` | Latin | Registered, planned; not selectable until content phases pass |

Japanese (`ja`) and Korean (`ko`) remain future roadmap languages and must not be exposed by this release.

## Capabilities, not language branches

Capabilities include dictionary, lessons, daily learning, Quiz, Flashcards, morphology, pronunciation, tokenisation, stroke order, and script-specific grid behaviour. Chinese keeps Pinyin and single-Han-character grid/stroke-order behaviour. English keeps word/headword grid and IPA. Malay receives its own affixation and normal Malay headword processing; it must not inherit Chinese character geometry or English-only linguistic assumptions.

## Versioned content identity

Every authored content record carries:
- `id`: immutable stable identity, never derived from a translated display string;
- `schemaVersion`: structural contract version;
- `languageCode`: language in which the item was authored;
- `contentVersion`: editorial revision;
- content-type fields and optional references to related records.

A correction to wording increments content revision; it does not change the identity. Deleting or replacing content must not silently orphan progress/history. Existing English/Chinese identifiers are retained and mapped explicitly; do not regenerate them from labels.

## Translation registry

A translation is a separate record keyed by content identity, source language, and target language. It records source revision, translation revision, status, provenance, and reviewer reference. Status values: `not_started`, `draft`, `machine_assisted_draft`, `legacy_unverified`, `reviewed`, `approved`, `stale`, `not_applicable`. `legacy_unverified` is a migration-only status for existing translations whose review provenance has not yet been confirmed; it is never equivalent to `reviewed` or `approved`.

An approved translation must have a reviewer reference. When its source revision changes, it becomes stale pending review; never overwrite reviewed work automatically. Missing translation is an explicit unavailable/fallback state, never an excuse to show unrelated text or silently relabel authored content.

## Runtime implementation and package inventory

The application loads the shared registry, content contracts, translation registry, language adapters and content-package registry before loading language data. The legacy bootstrap runs only after English/Chinese dictionary, lesson and Daily Learning sources are available. It wraps the original records and retains a `legacySource` reference so existing rendering and learning flows continue to receive their established data shape while new consumers can use the normalized package contract.

Version-controlled manifests live under `content/languages/en`, `content/languages/zh` and `content/languages/ms`. English and Simplified Chinese are active packages; Malaysian Standard Malay is registered as planned and is not selectable. The English and Chinese linguistic adapters preserve word-grid/IPA and single-Han/Pinyin/stroke-order differences. Malay has a separate `ms-MY` adapter contract for Malay affix-aware search, but no Malay learning content is active yet.

The shared package registry currently wraps the legacy Dictionary, Lessons and Daily Learning records and records Quiz/Flashcard source metadata. Quiz curriculum and answer-key rules remain in their secure pair-specific content pipelines; shared validation primitives handle language-pair and generic question-envelope rules. Existing raw IDs and records remain available through the compatibility reference; normalized package IDs are deterministic migration identities, not replacements for historical database IDs.

## Existing data compatibility

Legacy English and Chinese data will be migrated in place through adapters and explicit mappings. The first pass must preserve dictionary headwords/senses, Chinese Pinyin and stroke order, lesson IDs and progress, Quiz question IDs and approval state, Flashcard identities/session snapshots, Daily Learning activity identities, saved-word course keys, collection membership/order, user preferences, account ownership, and existing allowance ledgers.

Allowances remain shared by activity type across languages and retain their existing timezone reset/completion semantics. Dictionary search remains free and unlimited.

## Database migration strategy

Use expand → migrate → verify → contract. New nullable/compatible structures and registry support precede data conversion. Backfill in bounded batches with stable IDs, compare counts and references, then switch reads/writes only after parity is verified. Remove old en/zh-only constraints only after all callers, RPCs, policies, and historical rows are compatible. Production changes require reviewed migrations, disposable/local and staging tests, explicit owner approval, and the existing Live-before-frontend release order.

No production or staging database was changed in this Phase 1 implementation. The database migration work remains a reviewed design only; environment-specific migrations must wait for exact schema comparison and disposable/local plus staging migration tests.

## Validation

The core Node architecture/integration run passed 22 tests covering language activation boundaries, adapter behaviour, package wrapping and source preservation, translation registration and stale-state handling, question-envelope validation, and package identity rules. Additional repository tests have been added for application bootstrap order and content-source parity; their assertions were checked against the branch source, but those two new test files were not included in the 22-test local run. These are structural checks, not linguistic review or full browser/device regression.

A separate source inventory check confirmed English Dictionary 810 baseline + 506 expansion = 1,316 unique word/POS records; Chinese Dictionary 206 baseline + 519 expansion = 725 unique character records; English Lessons 17 base + 3 expansion = 20; Chinese Lessons 17 with 112 practice questions; Chinese Daily Learning 6 topics / 7 applications / 93 discovery records; and the Chinese Flashcard bank 519 character + 904 vocabulary + 24 expression cards. The Chinese Flashcard source remains explicitly draft and was not silently promoted. Existing account/progress/allowance history parity and database migration parity remain release gates.
