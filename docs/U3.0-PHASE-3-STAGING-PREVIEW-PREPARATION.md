## Read-only staging inspection

Inspection date: 2026-11-27. Project status: `ACTIVE_HEALTHY`; PostgreSQL 17.12.0.000. Existing English/Chinese rows and progress were not modified.

### Confirmed blockers

1. `public.languages` currently contains only `en` and `zh`; add an active `ms` registry row for staging.
2. `public.lesson_progress.learning_language` check permits only `en` and `zh`.
3. `public.lesson_practice_results.learning_language` check permits only `en` and `zh`.
4. `private.lesson_practice_attempts.learning_language` check permits only `en` and `zh`.
5. `private.learning_content_catalog.language_code` check permits only `en` and `zh`; there are currently no Malay catalogue records.
6. `public.saved_words.course` check permits only `en` and `zh`; extend to `ms` if saved Malay words are included in the preview.
7. `private.guard_lesson_progress_insert()`, `public.complete_permanent_lesson_for_language(...)`, and `private.record_completed_lesson_practice_result_for_language_impl(...)` explicitly reject languages other than `en` and `zh`.
8. Lesson completion is gated by `private.is_approved_learning_content(...)`; Malay lesson identities must be seeded into the catalogue before completion can succeed.
9. The existing Daily Discovery catalogue uses a 93-entry rotation contract. The approval function requires exactly 93 active entries with rotation orders 1–93. Preserve that contract for Malay; do not alter the existing English/Chinese discovery pools.
10. User preferences, daily activity sessions and activity logs reference `public.languages(code)`; the new language registry row is required for those foreign keys.

### Existing security controls to preserve

- RLS remains enabled on exposed user-data tables.
- User-owned progress/session policies must remain bound to `auth.uid()`.
- Lesson start and completion must retain server-side catalogue approval checks.
- Completion RPC must retain input validation, per-user advisory locking, row locking, replay behavior, and aggregate-result bounds.
- No answer-level data is to be inserted into the server-side catalogue.
- No user progress, preferences, entitlements, allowance usage, or saved-word rows are to be seeded or rewritten.

## Staging-only migration scope

The reviewed migration should be prepared in these bounded parts:

1. **Language registry:** insert `ms` into `public.languages` as active, idempotently.
2. **Language constraints:** extend the three lesson-language constraints and the catalogue language constraint to include `ms`. Extend `saved_words.course` to include `ms` only if the Malay dictionary save/sync path is part of this preview.
3. **Lesson server functions:** update the explicit language allowlists in the lesson-start guard, permanent-lesson completion RPC and practice-result implementation to accept registered `ms`, while preserving all existing authorization, catalogue identity, locking, replay and validation logic. Do not weaken the catalogue gate.
4. **Catalogue seed:** insert exactly 72 `permanent_lesson`, 60 `daily_topic`, 60 `daily_application` and 93 `daily_discovery` Malay catalogue identities. Daily Discovery must have unique rotation orders 1–93; all other activity records must retain null rotation order. Lesson/topic/application IDs and difficulty/topic mappings must match the feature-branch source exactly. Seed records as staging-only approved catalogue entries; this does not mean the linguistic content has received human approval.
5. **No Quiz/Flashcard scope creep:** do not modify Quiz or Flashcard language constraints or seed their content in the Phase 3 migration. Those belong to later phases unless a shared dependency is proven and documented.
6. **Idempotency and rollback:** use conflict-safe inserts; capture pre-migration row counts and constraint/function definitions; include post-checks and a forward-repair/rollback plan. Existing English/Chinese rows and progress must remain unchanged.

## Acceptance sequence after owner approval

1. Apply the reviewed migration to the dedicated staging project only.
2. Verify `ms` is registered and all intended constraints/functions accept it.
3. Verify catalogue counts and uniqueness: 72 lessons, 60 topics, 60 applications, 93 discovery entries; 20/20/20 difficulty balance for Topic and Application; Discovery rotation exactly 1–93.
4. Verify all Malay lesson start/completion/replay paths and all four Daily Learning activity flows, including adaptive Revision.
5. Verify English and Chinese lesson and daily activity paths remain functional and existing progress row counts are unchanged.
6. Run full CI and repository regression tests.
7. Perform browser/device acceptance on the staging URL, including desktop and mobile layout, language switching, sign-in/account isolation, lesson progress, daily completion/abandonment, and timezone/allowance behavior.
8. Run Supabase security/performance advisors and review RLS/function grants.
9. Only after these checks pass, send the staging preview URL and mark the Phase 3 staging gate complete.
